# plugin-fast-adapt 扩展调研（第二轮）：同类机制、论文算法与改进方案

日期 2026-11-06 ｜ 基线 v0.3.0（d7d824c，自检 226 项）｜ 承接 [2026-11-05 第一轮](./2026-11-05-扩展调研与设计依据.md)
本轮补第一轮没碰的两层：**迁移工具的机制设计**与**学术论文/算法**。证据口径三路分开：上游一手 issue、同类工具一手文档、论文原文抽验（承重引用逐一核实）。

## 一、第一性原理补全：管道六阶段，上一轮框架漏了「积累」

把「宿主单方面改接口，插件在无同步信息/节奏/权限下必须继续工作」拆到底，完整动作链有六段：

| 阶段 | 问题 | 现有覆盖 | 本轮调研判定的缺口 |
| --- | --- | --- | --- |
| ① 感知 | 版本变了没 | `guide-sync` dist-tags | 无 |
| ② 理解 | **变了什么** | 官方 upgrade-guide Markdown → 正则锚点 | **真源错位：文档是二手的、滞后的、且官方明说不保证记全**（§2.1） |
| ③ 判定 | 自己踩没踩 | `code-scan` 文本匹配 + 启发式降噪 | 同名符号撞车靠启发式而非结构证据 |
| ④ 验证 | 还能不能跑 | 内存冒烟 + typecheck + 可选真基类装载 | **「装了」≠「跑了」无读回证据；无隔离试装**（§2.2） |
| ⑤ 防患 | 写新代码别踩 | 4 条常设契约机械检出 | 弃用预警缺失（§3.3 第 5 条） |
| ⑥ 积累 | 这次踩的下次别再踩 | **无** | **误报/漏报修完就丢，无夹具、无案例库**（§2.4） |

第一轮的四动作框架覆盖①—⑤，⑥完全缺位——这不是遗漏一项，是缺了「技能随时间变好」的半边循环。下面四个方案按②④⑥⑤各补一段，①不动。

## 二、三路证据

### 2.1 上游一手事故（GitHub Discussions 实锤，承重条目已抽验原文）

最重的一条，[discussion #5816](https://github.com/deepseek-ai/deepseek-harness/discussions/5816)，官方自述（已核原文）：

> "Public APIs are pre-stable; update every consumer…" 命名契约与改名账本明确写着 "No alias, compatibility package, duplicate service key, dual event name, or fallback parser remains. The repository rejects the old name."

六天移除两个公开 surface（`UserQuestionService.registerProvider`、整个 ApiProxy 包），npm 上照常干净安装，**无任何 removal 信号**。这意味着：②的「变了什么」不能只信文档——官方立场就是文档可以不留兼容痕迹。

### 2.2 迁移工具机制拆解（一手文档）

| 工具 | 机制 | 抄什么 |
| --- | --- | --- |
| Kotlin [binary-compatibility-validator](https://github.com/Kotlin/binary-compatibility-validator) | `apiDump` 把公共 API dump 成人读 `.api` 文件入库作 golden，`apiCheck` 挂进 CI diff；有意变更→重 dump→人工审 diff | **API 面作为一等公民工件**：快照入库、diff 出变更清单，不依赖 changelog |
| [oasdiff](https://github.com/oasdiff/oasdiff) | 两版 spec normalize 后 diff，351 种 breaking 分类、三级 severity（error=确定破坏/warn=无法确证/info=非破坏），带稳定 change fingerprint | **表驱动分类学 + 三级 severity + fingerprint**（去重键） |
| [jscodeshift](https://github.com/facebook/jscodeshift) / [Codemod 平台](https://docs.codemod.com/community/package-structure.md) | transform 三态（ok/nochange/skip）、dry-run 预览、`__testfixtures__/X.input.js+X.output.js` 配对回归；codemod.yaml 把迁移打包成带版本对关键词的可分发单元 | **夹具配对资产 + 四档严格度（strict/cst/ast/loose）** |
| [OpenRewrite](https://docs.openrewrite.org) | recipe = 带元数据的声明式变换单元，硬约定幂等、单循环收敛；**由库作者随自己的包发布迁移 recipe**（Spring Boot 系列为实证） | 「宿主发布 migration card」同构成立，但官方不配合时自建 yaml 卡是二期 |
| [Renovate](https://docs.renovatebot.com/key-concepts/automerge/) | major 独立分支试跑，automerge 判定是「必需检查全绿」纯机械标准；每轮只 merge 一个，失败转人工 | **独立环境试跑 + 机械判定** |
| [Amazon Q Java 升级](https://docs.aws.amazon.com/amazonq/latest/qdeveloper-ug/how-CT-works.html) | 生成 transformation plan → 编辑 → build+测试迭代 → 输出 **plan-vs-actual 差异**，接受才落盘 | 报告形态：计划 vs 实际差异 |
| Anthropic [AI code migration 六步制](https://claude.com/blog/ai-code-migration)（2026-07） | 先建 judge 且**先验证 judge 对故意破坏的代码必失败**；机械可恢复队列；对抗 reviewer 发现重复错误时不修文件、改 rulebook 一句话再重放受影响批次 | **失败案例的积累载体是 rulebook 本身** |
| [@eslint/migrate](https://eslint.org/blog/2024/05/eslint-configuration-migrator) | 机器做 1:1 语法翻译，官方明说不自动化语义项，产出「get you very close」+人工清单 | 报告分「自动节+人工清单节」 |

### 2.3 论文与算法（承重引用已逐篇核验）

| 论文 | 核心算法 | 适用判断 |
| --- | --- | --- |
| [APIDiff（SANER 2018）](https://github.com/aserg-ufmg/apidiff) | 两版源码逐类型比对成员签名，归类 breaking/non-breaking | 抄「规整化快照+分类学」形态，实现（Java 反射）不可抄 |
| [npm breaking changes 实证（arXiv 2408.14431）](https://arxiv.org/abs/2408.14431) | 381 热门项目带标注数据集，**95.4% breaking changes 在 release notes 有记载** | 反向支持现有「抽指南」路线：文档缺失是少数但致命（正好是 #5816 那类） |
| [SemDiff/migration cards（TOSEM 2011）](https://www.cs.mcgill.ca/~martin/papers/tosem2011.pdf) | diff 框架仓「框架自己适配自己破坏性变更」的提交，归纳成迁移卡 | 上游仓吃狗粮 commit 是现成 before/after 对来源，二期 |
| [BBCFixer（arXiv 2610.09267）](https://arxiv.org/abs/2610.09267) | 同一调用点在老/新库版本**差分执行**，返回值有差分即定位根因 API，用根因过滤喂给修复 agent | 「差分执行」比全文 diff 证据强一个量级，验证阶段可借 |
| [BUMP（arXiv 2401.09906）](https://arxiv.org/abs/2401.09906)（Maven 生态 571 例） | breaking 更新固化成一行版本变更 + 容器隔离，构建失败即复现 | 夹具形态参照：每条事故配最小复现 |
| [CodePlan（微软）](https://arxiv.org/abs/2309.12499) | 仓库级编辑=依赖图排序的位置编辑链+每步反馈 | 骨架思想；fleet 多插件批量时才用得上 |
| [Skill 迁移评估回顾研究（arXiv 2609.30120）](https://arxiv.org/abs/2609.30120)（已核摘要） | 对一个已上线插件升级 skill 做 64 报告回溯评估，发现判据漏洞（「containment predicate 接受父目录仍满分」），判据必须可执行、可追溯契约域 | **这就是本技能的验收方法论**：4 条常设契约各配 executable probe，先证伪再信 |
| [typescript-eslint no-deprecated](https://typescript-eslint.io/rules/no-deprecated) | TS type checker 读符号 deprecated 标志，对每个使用点报错 | 直接可抄：插件 typecheck 开此规则，弃用预警变机器可判 |

未找到/证伪记录：APIKeeper、LibCup（ICSE 2023）、CrossApi 未找到可核实出处；GumTree/MTDIFF（AST diff）对本管道优先级低——ts-morph 出规范化快照更轻；Coccinelle 思想（带元变量的模式-替换对）可借鉴但引擎绑 C。

## 三、改进方案（按管道阶段各补一段，可独立拍板）

### 方案 A：宿主 API 面快照 diff —— 把②的真源从「文档」补成「文档+包本身」（P0）

**针对**：痛点①指南滞后 + ②锚点误报 + 事故#3「已删 API 无信号」。官方立场（#5816）决定了文档必然缺记，**包本身才是唯一不撒谎的源**。

**依据**：Kotlin binary-compatibility-validator 的快照模式 + oasdiff 分类学 + APIDiff。本机已实证可行：`~/.local/lib/node_modules/@deepseek-ai/dsh/node_modules/@deepseek-ai/` 下 **306 个宿主包全部带 `.d.ts`**，`exports` 字段规范声明 `types` 入口；guide-sync 缓存已有 `releases/` 目录可提供第二版本源。

**做法**（一期刻意收窄）：
1. 新增 `scripts/lib/surface.mjs`：解析 package.json `exports` → 逐入口抽 `.d.ts` 顶层导出符号（`export declare class/interface/function/const` + `export {…}` + `export * from` 展开），输出规范化 JSON 快照（包名→入口→导出符号集）。
2. 新增 `scripts/api-diff.mjs <插件目录> --from <版本> --to <版本>`：两版快照 diff，输出三级清单：`removed`（确定破坏，对齐 P0）/`renamed`（removed∩added 的近似对，对齐 P1 待裁量）/`added`（非破坏）。
3. **双源账本**：包面 diff 与指南锚点表对账——文档说了而包面没有的（文档夸大）、包面变了而文档没说的（`doc-gap`，正是 #5816 类）分开标注；`code-scan` 锚点扩为「指南锚点 ∪ 包面 removed」双源，命中带 `source: guide|surface|both`。
4. 每份快照带 fingerprint（变更类型+符号+版本范围哈希），供方案 C 去重。

**验收**（墨菲）：拿 0.2.1-rc.5 vs 0.2.2-rc.1 实跑，断言能自动发现至少一条指南没写而包面真实消失的导出（#5816 类复现）；反例：包面 diff 与指南重复报同一变更时须去重为 `both` 不双报；`export *` 展开在至少一个真实宿主包上核对无漏。

**奥卡姆边界**：一期只做「符号存在性」，不做签名级参数 diff（二期、需 ts-morph）、不做行为变更检测（静态不可判）、不引 TypeScript 编译器依赖（正则抽导出，宁可窄报不误报，与现有降噪纪律一致）。

### 方案 B：真宿主读回验证闭环 —— 把④从「冒烟」升到「读回证据」（P1，成本与风险最大，单独拍板）

**针对**：痛点③ + 事故#1/#2/#4/#6（peer hoist 延迟爆炸、覆盖层残留、激活不可观测、无地面真值）。

**依据**：Renovate 独立分支试跑 + Amazon Q plan-vs-actual + Renovate「机械判定」；上游 #10776 证明必须读回注册表而非看 install 输出。

**做法**：
1. 扩展现有 `run.mjs --real-smoke` 档为独立 `scripts/real-verify.mjs`：在**隔离 `DSH_HOME`**（临时目录，绝不动 `~/.dsh`——#12290 桌面重置 `$DSH_HOME` 蒸发全 workspace 的教训反向利用）+ 独立 worktree 装目标 rc 宿主与插件。
2. 验证判定三件套，全部机械：①真装后**读回 profile bundle 注册表**确认激活条目存在（不是看 install 退出码）②冷启动跑一轮，collect 宿主日志的 activation 信号 ③peer hoist 红旗检查：装完 diff 隔离 node_modules 里 `@deepseek-ai/*` 的包数，多出来的就是 #11143 类 hoist 迹象。
3. 报告加 plan-vs-actual 节：本次扫描计划修的 N 条 vs 实际验证通过 M 条，未过的带完整 build/启动日志降级为 P0 证据。
4. **结论分级**（吸收 #170 教训）：「迁移成功」断言降级为「读回证据支持」；判分/断言通过不作为正确性证明，只作证据之一。

**验收**：对一个已知 peer hoist 事故形态的插件（复刻 #11143 最小样例），real-verify 必须在冷启动前报出 hoist 红旗；隔离环境跑完后用户真实 `~/.dsh` 的 mtime 清单零变化（防自己成为事故源）。

**奥卡姆边界**：不做全自动修复循环（LLM 修 breaking change 的 Byam/BBCFixer 路线留观察）；不默认全量插件跑（成本高，先接 `fleet-sweep` 的红旗名单）；装宿主 306 包的隔离环境耗时需实测，超过 10 分钟就降级为「只装被查插件+其直接依赖」。

### 方案 C：失败案例库与回归夹具 —— 补⑥从无到有（P1，成本最低，建议与 A 同批）

**针对**：痛点④（无失败积累）。**每一轮实战修掉的误报/漏报都是一次性消耗品**——第一轮文档里「判据收窄过三轮（35 处全误报）」这种教训，换台机器重跑就没了。

**依据**：jscodeshift 夹具配对 + Anthropic rulebook 回写 + oasdiff fingerprint 去重 + [arXiv 2609.30120](https://arxiv.org/abs/2609.30120) 的「判据可执行、可追溯」要求。

**做法**：
1. `fixtures/` 目录，每条 = 一个真实事故切片：`<id>/input/`（触发误报/漏报的最小插件文件）+ `<id>/expected.json`（该输入的正确判定）。self-test 启动时扫 `fixtures/` 全量回归，`--update-snapshots` 显式更新。
2. 回写纪律（写进各子技能 SKILL.md 的跨车道纪律节）：修一次误报/漏报 = ①写回 `references/heuristics.md` 判据 ②沉淀夹具 ③报告 fingerprint。三件缺一，下次照踩。
3. 案例库登记表 `references/incident-ledger.md`：每行 = fingerprint、事故一句话、来源（本机实测/上游 issue 链接）、对应夹具 id。第一轮的 GIT_CONFIG 残缺组、软链删除两项为首批入库。

**验收**：故意把某夹具的 expected.json 改坏（或输入文件改坏），self-test 必须红且指名是哪个夹具；夹具数与 incident-ledger 行数双向对账（复用现有双向断言模式）。

**奥卡姆边界**：不做自动「从 issue 抓取生成夹具」（人工切片，每条 10 分钟内）；不做跨机器分发（夹具进技能面随 npm 走，天然分发）。

### 方案 D：事故驱动机械预检 + 弃用预警 —— ⑤的小增量顺手做（P2）

每条都有上游实锤 issue，纯机械可判，逐条独立可做：

| 检查 | 依据 | 落点 |
| --- | --- | --- |
| package.json UTF-8 BOM 检测 | #12322 | `write-gate` + `env-doctor` 各加一条，3 字节头判断 |
| 依赖名撞 Node core 模块 | #10761 | `write-gate` 内置 Node core 列表比对 |
| 中断升级/回滚死锁 runbook | #11886、upgrade-skill 中断安装卡 | `references/` 新增 runbook 一节（纯文档） |
| HMR 双语义边界说明 | #12301/#10774 | adapt 车道「改完验证」节补一句：热替换留 ESM 缓存，验证结论以重启后冷启动为准 |
| 弃用预警：typecheck 建议开 `typescript-eslint no-deprecated`，从宿主 `.d.ts` 抽 `@deprecated` 成员表作「即将 breaking」锚点 | §2.3 方向 5 | 文档先行（references 指路），机械抽取二期跟方案 A 的 surface.mjs 同源 |

### 砍掉的方案（奥卡姆记录，避免重提）

| 方案 | 为什么不采 |
| --- | --- |
| AST 全量 codemod 化（jscodeshift/ts-morph 改写插件代码） | 本技能定位是「报命中+官方修法」，不自动改插件代码是既有安全边界；AST 修复引擎需要海量语料（APIFix 的 ReFazer 路线），当前没有 |
| 独立「持久化兼容」第五车道 | 第一轮已裁定归 adapt 判据，本轮无新证据推翻 |
| 「迁移卡结构化」单独立项 | 方案 A 的双源账本 + 方案 C 的夹具合起来就是它的全部增量，单开会造成 A/C 两个半成品；OpenRewrite 式「由库作者发布 recipe」需上游配合，先不指望 |

### 5.2 实现引入的五个新问题（本次全仓逐处核实，非推测）

1. **安全边界节与实现自相矛盾（P0，文档级）**。SKILL.md 安全边界节仍写「**不自动改插件代码**：只报命中和官方修法」，但 `codemod.mjs --apply` 落盘改代码、`fix-peer-deps --apply` 改 `package.json`（后者 d7d824c 就进了）。这恰好是上游 [#12301](https://github.com/deepseek-ai/deepseek-harness/discussions/12301)（文档说重启、实态热替换）的同款病：文档与实态相反。[arXiv 2609.30120](https://arxiv.org/abs/2609.30120) 的教训直接适用——判据必须可执行、可追溯，声明边界是最先被追溯的一环。
2. **闭环断开：合成指南无消费者（P0，功能级）**。`types-diff --synth` 写入 `~/.cache/dsh-plugin-fast-adapt/synthesized-guides/`，全仓 grep 只有 types-diff 自己引用该目录；`code-scan` 的指南加载走 `loadGuides(guideRoot, version)`（guide-sync 快照），`run.mjs` 不编排 types-diff。CLI 输出「可直接注入扫描走廊」目前没有注入路径。「发版即适配」的实际状态是**能算出 diff，但 diff 进不了扫描**。
3. **规则计数漂移（P1，文档级）**。dbea17d 一笔加了三条规则（lifecycle/vendor-rescope/waterfall，提交信息只说「第 5 条」），`lib/standards.mjs` 表内实际 7 条且三条都接了检测器（standards.mjs:236-252），SKILL.md 却写「机械可判的 5 条」且枚举漏了 vendor-rescope 与 waterfall。断言数门禁数得到 `test()` 声明数、数不到规则枚举——与第一轮发现的「数量对得上≠每条都过」同类盲区。
4. **两版签名来源依赖「恰好装过」（P1，操作级）**。`--current --save` 只能快照当前装机版；`--from` 只认本地路径或已缓存签名。错过升级时点，旧版签名永久拿不到。快照的成立前提被压在「升级前记得先存」的用户纪律上，而这条纪律没写进任何 SKILL.md 流程。
5. **三条新规则无真实插件场测（P1，质量级）**。lifecycle-unpaired-resource 判据是「整模块找不到配对注销」——注册与注销跨文件（a.ts 注册、b.ts dispose）必误报；waterfall-missing-next 的「作用域内未调用 next()」对 next 透传给内层函数的写法也会误报。第一轮实测教训是「35 处命中全是常量表」「误报一次，使用者就不再信第二次」；新规则只有合成用例自测，没有 fleet 场测记录。
